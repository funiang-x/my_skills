# 阶段状态 —— `PROJECT.md` 与迭代落点

> 本文件是 [`骨架总则.md`](骨架总则.md) §2 的「状态契约」。
> 解决的问题：**AI 换一次会话就不记得"上一步做完没、基线是什么"**，于是迭代退化成
> 靠人在对话里复述。`PROJECT.md` 就是这件事的单一真相源。

## 1. 放哪

**工程根目录的 `PROJECT.md`，跟 git 走。**

跟 git 的理由：状态属于**那个工程**，不属于库里、不属于会话；换机器、换 agent、
换一个月后回来，读它就恢复现场。

## 2. 六个字段（一个不多）

模板（照抄，替换 `<>`）：

```markdown
# PROJECT

阶段: <走哪条线 + 第几步，如「工程线 ②改」>

交付物: <逗号分隔；每项写成 `名字✓ 或 ✗`，✓ 的必须能指到文件路径>

门禁基线: <六件事的名字=退出码，改前必须记，如 env=0 build=0 test=0 lint=0 size=0 selftest=0>

待办: <下一件要做的事，按顺序；一句一件>

回退点: <时间 + 一句话 + 锚点（git 短 sha），如 2026-10-01 骨架派生完成 abc1234>

下一步判据: <可复现的判据，如 `fw.py test` 退 0 且 RTT 打出 BOOT_OK>
```

字段约束：

| 字段 | 取值约束 | 说不清会怎样 |
|---|---|---|
| `阶段` | 必须能对上 `WORKFLOW.md` §2 的阶段名 | 判不出阶段 → 按 [`骨架总则.md`](骨架总则.md) 判不准就问人 |
| `交付物` | 每项 ✓ 要能指到文件；指不到就写 ✗ | 写 ✓ 但指不到 = 伪造进度 |
| `门禁基线` | 六件事全列，没跑过的写 `-`，**不许省略** | 省略 = 改完没有对照，无法证明变好 |
| `待办` | 一句一件，按顺序 | 攒成一坨 = 下次没人知道从哪继续 |
| `回退点` | 必须带锚点（sha / tag / 时间戳） | 没锚点 = 回不去 |
| `下一步判据` | 必须可复现（命令 + 期望结果） | "功能正常"这类词等于没写 |

## 3. 什么时候写（**这条决定它会不会烂掉**）

**只在两种时刻写，别的时候一个字都不动：**

1. **跨阶段**：阶段字段要变，或某交付物从 ✗ 变 ✓
2. **改基线**：门禁基线刷新，或设新回退点

日常改代码、跑构建、修 bug —— **不写**。把"每次编辑都同步"当规矩，它就必然烂成没人维护的文件。

## 4. 阶段判定：AI 推 + 脚本判

**判定分两问，别混：**

| 问 | 谁答 | 依据 |
|---|---|---|
| 现在处在哪个阶段？ | **AI 读 `PROJECT.md` 推断** | `阶段` 字段 + 交付物勾选状态 |
| 这一步的判据满足了没？ | **脚本回答**（门禁 + 自检脚本） | 退出码 |

**两者不一致时以脚本为准**，并把不一致记成一条坑：
那说明 `PROJECT.md` 的状态字段过期了——**过期本身就是信号**，比字段本身值钱。

**为什么不让脚本硬判阶段**：覆盖不全时就只能猜，而猜出来的阶段号不可复现，
你又没法追问"它凭什么说现在在第 ④ 步"。AI 推 + 脚本判，两个人各答自己能答的那半。

## 5. 迭代与回退（真实节奏是回退，不是流水线）

改任何参数之前，按顺序做三件事：

1. **确认基线**：`门禁基线` 填了没？没填就现在跑一遍填上——不知道改前什么样，
   就没法证明改后更好。
2. **查同步表**：`WORKFLOW.md` §5 的「改一处，必须同步哪几处」。
   改引脚就同步 `.ioc` / `board_config.h` / 网表，**一次改完**，别分几次。
3. **重跑判据**：以 `下一步判据` 为准。

**门禁由绿转红时停手**——先修红，不要在此基础上继续加东西。
回不去就退到 `回退点`，把失败现象记进 `坑册.md`。

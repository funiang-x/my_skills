# 适配层契约 —— 怎么加一颗新芯片

> 本文件是**唯一**的扩展入口。想接入新芯片，只做这里写的 7 件事；改别处一律算越界。
>
> 现状：唯一实现是 STM32（`stm32-hal-cli-flow/`）。ESP32 / nRF / GD32 **留了位、没实现**——
> 不是遗漏，是刻意保持骨架只被一份实现拉着走。

## 0. 一条硬约束（踩过的坑）

**适配层目录必须在库根一级**，且里面要有 `SKILL.md`。

为什么：各客户端（`.agents/skills`、`.trae-cn/skills`、`.codex/skills`）只扫**库根一级目录**里
的 `SKILL.md`。放成 `adapters/<chip>/SKILL.md` 这种嵌套结构，**不会被任何客户端发现**，
只能靠人手点路径——跨 agent 就退化成靠自觉。

所以：**芯片所在的那一层就是目录名的前缀**（`stm32-hal-cli-flow`、将来的 `esp32-idf-flow`），
而不是把芯片塞进 `adapters/` 子目录。`framework/` 这种纯文档目录不在此列（它不被当 skill 装载，
由 `ROUTE.md` 指向即可）。

## 1. 七项，缺一不可

| # | 项 | 放哪 | 机器判据 |
|---|---|---|---|
| 1 | 芯片标识 | 适配层 `SKILL.md` 的 front-matter | 能解析出 `id` / `family` / `core` 三个键 |
| 2 | 工具链三元组 | 适配层 `工具链.md` | 编译器 / 构建器 / 探针各自的**探测命令**写在表里，且探测命令在本机退 0 或明确报缺失 |
| 3 | 物理能力四问 | 同上 | `flash` `reset` `日志` `调试` 四项：**有 = 写命令，无 = 明确写 `none`**，不许留空 |
| 4 | 门禁实现位置 | 适配层 `SKILL.md` 指向工程内 `Tools/fw.py` | 该文件存在，且 6 件事各有对应子命令（见 [`工程契约.md`](工程契约.md)） |
| 5 | 模板位置 | 适配层 `模板.md` | 目录存在，且能从它派生出一个首次构建零告警的骨架 |
| 6 | 板级差异清单 | 适配层 `板级差异.md` | 逐条写"换芯片必须同步哪几处 + 每处的判据"；**不许写"参考文档"了事** |
| 7 | 坑册 | 适配层 `坑册.md` | 存在即可为空；每条必须是"现象 → 根因 → 处置" |

## 2. 适配层声明（front-matter）

模板（`<...>` 是占位，照抄后替换）：

```yaml
---
name: <适配层 skill 名，与目录名一致>
description: <一句话：什么芯片 + 什么时候用它。要把触发词写进去>
chip:
  id: <stm32f4 | esp32s3 | nrf52840 ...>
  family: <STM32F4 | ESP32-S3 | nRF52 ...>
  core: <cortex-m4 | xtensa-lx7 ...>
toolchain:
  compiler: <arm-none-eabi-gcc>
  builder: <cmake+ninja>
  probe: <jlink | stlink | esptool | none>
---
```

**为什么用 front-matter**：机器可读的最小结构化数据，不引入 JSON/YAML 依赖
（`Tools/` 里的检查器按行解析，只用 Python 标准库）。

## 3. 加一颗新芯片的操作步骤

1. **照 [`适配层契约.md`](适配层契约.md) §1 建 7 项**——复制 `stm32-hal-cli-flow/` 的目录形状
   当脚手架（七项一个不少，内容按新芯片重写）。
2. **front-matter 填新芯片**（§2）。
3. **探工具链**：把编译器 / 构建器 / 探针的探测命令**在本机真跑一遍**，把输出填进 `工具链.md`。
   探不到就写"缺失 + 安装指引"，**不许猜路径**。
4. **建模板**：从现有工程里剥出骨架（保留结构、清掉板级值），放 `templates/<id>/`，带 `NOTICE.md`。
5. **登记路由**：在 `ROUTE.md` §2 的对应行里加上新 skill 名（否则 agent 装载不到它）。
6. **登记阶段**：`WORKFLOW.md` 的「必载 skill」列若涉及它，一并加；跑 `python tools/skillman.py doctor`。
7. **记一条坑**：把你接这颗芯片时踩的第一个坑写进 `坑册.md`——空坑册意味着"没真跑过"。

**验收判据**：新芯片的模板能派生出一个 `fw.py env` 退 0 的工程；且骨架层（`framework/`）
**一个字都没改**（改了就说明有芯片相关的值漏在骨架层，回去把它挪下来）。

## 4. 降级路径（装没装都能开工）

适配层的每项能力都要写清"没有它怎么办"：

| 能力 | 有 | 没有时 |
|---|---|---|
| 构建 | `fw.py build` | 报环境缺失 + 给安装指引，不猜路径 |
| 烧录 | J-Link / esptool 命令 | **转人工**：输出命令给你手跑，AI 不代跑设备动作 |
| 日志 | RTT | 走串口（STM32 已有 `Debug-UART` 预设这条降级） |
| 调试 | JLinkGDBServerCL + gdb | 只用日志取证，不承诺寄存器现场 |
| 门禁 | `Tools/fw.py` | 缺哪个子命令就报"契约第 N 项未实现"，**不许假装过** |

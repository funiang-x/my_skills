# 骨架总则 —— 芯片无关的工作流骨架

> 本文件是 `framework/` 的入口。它只回答一个问题：**这套工作流的哪些部分与芯片无关。**
>
> 分工不许混：`ROUTE.md` 说「用哪个 skill」· `WORKFLOW.md` 说「按什么阶段做」·
> `framework/` 说「**哪些东西换芯片不用改**」。

## 1. 三层，改哪层由改什么决定

| 层 | 位置 | 内容 | 换芯片时 |
|---|---|---|---|
| **骨架层** | `framework/` · `ROUTE.md` · `WORKFLOW.md` | 阶段序列、交付物、验收判据、工程契约、状态契约、AI 边界 | **一行不改** |
| **适配层** | 库根 `<chip>-*/SKILL.md`（每颗芯片一个目录） | 芯片的构建/烧录/调试/取证规程、工具链、板级差异清单、坑册 | **换一个目录** |
| **项目层** | 工程仓库内 | 源码、`Core/Inc/board_config.h`、`.ioc`、`PROJECT.md` | **新建一个工程** |

**判据**：凡是要读"某颗芯片的手册 / 某个探针的命令"才知道的值，**不许出现在骨架层**。
骨架层只能出现指针。

**加一层新芯片 = 照 [`适配层契约.md`](适配层契约.md) 新增一个适配层目录，骨架层不动。**
这条是整套设计的兑现方式——做不到就不是"可复用"。

## 2. 五份契约（骨架层全部内容）

| 契约 | 文件 | 定义什么 |
|---|---|---|
| 适配层契约 | [`适配层契约.md`](适配层契约.md) | 一颗新芯片要提供哪 7 项才算可接入 |
| 工程契约 | [`工程契约.md`](工程契约.md) | 一个工程要能回答哪 6 件事才算能干活 |
| 状态契约 | [`阶段状态.md`](阶段状态.md) | `PROJECT.md` 的字段 + 阶段判定 + 迭代/回退落点 |
| 跨端契约 | [`跨端就绪.md`](跨端就绪.md) | 任何 agent 靠什么进入这套流程；已知弱点 |
| 集成契约 | [`外部集成.md`](外部集成.md) | 什么该走本地 CLI、什么该接外部服务（含 MCP）；接进来的四条硬要求 |

## 3. 冲突裁决顺序

**安全（人 > AI）→ 单一真相源（门禁 / 表格 > 记忆 / 口头）→ 效率。**

skill 输出与门禁脚本冲突 → **以门禁为准**，并记一条坑册。理由：门禁是机器裁决，可复现；
skill 是规程，会被压缩、会被记错。

## 4. 单一真相源（每条只有一个正本）

| 事实 | 正本 | 谁不许重复写 |
|---|---|---|
| 引脚分配 | 工程内 `Core/Inc/board_config.h` + `.ioc` | 任何 skill、任何文档、任何 `AGENTS.md` |
| 能不能干活 | 工程内 `Tools/fw.py`（6 件事） | 本库任何文档不得复述命令输出 |
| 现在做到哪 | 工程内 `PROJECT.md` | 会话记忆、commit message |
| 任务→skill 映射 | `ROUTE.md` §2 | `WORKFLOW.md`（它是复述，由 `skillman.py doctor` 防漂） |
| 阶段→交付物 | `WORKFLOW.md` §2 | 任何 skill |

## 5. AI 边界（正面清单：能做这些）

**能做**：产结构化交付物（连接表 / 代码 / 命令 / 文档）· 跑门禁与判据 · 核对一致性 ·
生成或修改 `.ioc` 与生成代码 · 写沉淀草稿。

**动手前必须先问人**（不是"不许做"，是"必须先问"）：
擦片 · 改芯片配置的引脚或时钟 · 烧录 · 复位目标 · 下单打样 · 改第三方大件的正本。

**铁律**：不编造数值。器件参数查手册，寄存器位定义查 CMSIS 头，路径端口版本查机器上的实际文件。

## 6. 本文件不写什么

不写命令、不写芯片名、不写路径数值、不写阶段清单——它们各自有正本（§2、§4）。
本文件一旦开始写这些，就成了第二份规则正文，两边必然漂。

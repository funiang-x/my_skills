> 本文件是 [`adapter.md`](adapter.md) 第 2、4 项的展开：**探测命令**与**六件事的对应关系**。
> 值会过期，命令不会——所以这里给命令，在 §1 给一份带日期的缓存。

## 1. 探测命令（**唯一权威**）

```powershell
$env:PYTHONIOENCODING='utf-8'; python Tools/fw.py env
```

**先设环境变量，否则 GBK 控制台下必崩**（`⇒` 触发 `UnicodeEncodeError`），
症状看起来像"门禁失败"。别用 `Get-Command` 猜——`fw.py env` 会报出真实路径、
依赖源码是否齐全（ST HAL / CMSIS / FreeRTOS / SEGGER RTT）、J-Link 工具包与
`JLink.exe`/`JLinkRTTLogger.exe`/`JLinkGDBServerCL.exe` 三项、以及各预设构建目录是否已配置。

## 2. 三元组的替换位

换编译器 / 构建器 / 探针时，要动的就这几处（**其余不许动**）：

| 换什么 | 动哪 |
|---|---|
| 编译器 | `cmake/gcc-arm-none-eabi.cmake`（工具链文件）· `cmake/proj_warnings.cmake`（告警档位） |
| 构建器 | `CMakePresets.json` 的 `generator` |
| 探针 | `Tools/fw.py` 里 J-Link 相关命令构造 · 本文件 §3 的能力表 |

## 3. 六件事 → 子命令（对 [`framework/工程契约.md`](../framework/工程契约.md) §1）

| # | 契约项 | 命令 | 通过判据 |
|---|---|---|---|
| 1 | 体检 | `fw.py env` | 退 0，且四项依赖源码"齐全" |
| 2 | 零告警构建 | `fw.py build --clean-first`（每个预设各自跑） | `warning` + `error` 总计 **0** |
| 3 | 脱硬件测试 | `fw.py test` | 退 0，**不需要板子** |
| 4 | 配置对账 | `fw.py lint` | 退 0（`.ioc` ↔ `board_config.h` 无确定性矛盾） |
| 5 | 体积预算 | `fw.py sizecheck` | 退 0 |
| 6 | 门禁自检 | `fw.py selftest`（发布前加 `--full`） | 基线全绿 **且** 负向用例逐条报错 |

**第 6 件的判据是两件事**：检查器必须**非 0 退出**，**且**输出里出现注入的标记串。
只看退出码会被"脚本崩了"骗过。

## 4. 一次跑完（交给 AI 的起手式）

```powershell
$env:PYTHONIOENCODING='utf-8'
python Tools/fw.py test
python Tools/fw.py lint
python Tools/fw.py build --clean-first
python Tools/fw.py sizecheck
python Tools/fw.py selftest
```

**顺序有理由**：`test` 最便宜（秒级、不用板子）⇒ 先跑它，业务逻辑的错误该在这一步抓完。
`lint` 也便宜且是 `verify` 的前置——lint 不过就不该浪费一次烧录。
`build --clean-first` 必须每个预设各跑一次：增量构建只重编改动过的文件，**看不出新告警**。

**要结论就读退出码**（表见 `SKILL.md` §5），不要读输出措辞。

## 5. 与骨架层的关系

本文件里的每个命令都带 **STM32 或 J-Link 的字样**——所以它属于适配层。
`framework/` 只写"必须有体检、必须零告警、必须能脱硬件测"这类**判据**，
一旦 `framework/` 里出现了 `fw.py` 或 `J-Link`，就是分层漏了，把它挪回这里。

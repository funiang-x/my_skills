# 工作流七步 —— 每步的判据、动作、常见坑

> 顺序固定。**跳过①或②** = 后面全是猜。

---

## ① 划范围

**动作**：`scripts/inventory.py <工程根>` —— 出目录树 + 文件类型统计，自动排除
`build/ _work/ _archive/ .git/ node_modules/ Middlewares/ Drivers/` 这类非自研目录。

**判据**：能回答"这个工程里**自己写的**代码有多少个文件、几层目录"。

**常见坑**：
- 把 vendor/HAL/第三方算进"自研" ⇒ 关系图被淹没。先划边界，再读。
- 反过来漏掉**生成物**（`.ioc`、CubeMX 生成的 `.c`）—— 它们是一手资料里**最容易推翻文档**的那类。
  生成物要**单独列一类**，既不算"自研"也不算"第三方"。

---

## ② 取一手

**动作**：
- 源码：**读全文**（不是 grep 关键词就下结论）。`scripts/relations.py` 抽函数定义、
  函数调用边、`#include` 依赖 —— 用来**定位**，不用来代替阅读。
- 原理图：`scripts/netlist.py` 取活体网表。⚠️ **必须带元件值**：
  只读"连接关系"看不到 `10µF` 还是 `100nF`，而那两个值会改变整个结论。

**判据**：每个后面要写进表的量，都能指出"哪个文件的哪一段"。

**常见坑**：
- **网表工具常常不给元件值**（只给连接 + 料号）。要另取一路（本库 `easyeda-agent` 的
  `sch list` 有 `otherProperty.Value`）再合并 —— 见 `scripts/netlist.py` 的实现。
- 元件值字段与料号**可能自相矛盾**（Value 写 `10µF`、料号是 `100nF` 件）。
  这类矛盾**不要自己判对错**，直接进风险链的待确认。
- 只读代码不读 `.ioc`/生成物 ⇒ 会漏掉"文档说的参数根本没落地"这种最大的一类冲突。

---

## ③ 对口径

**动作**：找工程自带的仿真/门禁/复算脚本，问三个问题：
1. 它的输入从哪来？（是不是从图纸/网表 1:1 抄的，还是手写的第二份真相源？）
2. 它的**量纲口径**与实现一致吗？（相位展开没展开？log 域还是线性域？归一化系数一样吗？）
3. 它测的**对象**与实现测的对象是同一个吗？（会不会悄悄量了上一版文件？）

**判据**：能写出"仿真口径 = 实现口径"或"**不一致，差在 X**"。

**常见坑**（都是真实踩过的）：
- 仿真用了 `np.unwrap`，固件存 `atan2` 主值 ⇒ 仿真把 180° 的插值缺陷藏了，长期绿灯。
- 仿真里运放宏模型极性反、把负载双重计数、驱动源钉死 ⇒ **模型错不是电路错**。
- 仿真建标定表用的是**标称值**，而固件建表用的是**测出来的值**。
> **判据一句话**：仿真绿 ≠ 电路对。**先怀疑模型，再怀疑电路。**

## ④ 搭链

**动作**：`scripts/scaffold.py --topic <主题> --out <工程根>/docs/chain` 生成骨架，然后按顺序做三件事：

1. **先定主干**（这一步不能跳）：这个工程的那条通路是什么 —— 信号通路？状态迁移？请求生命周期？
   在 §1 里写清"从哪走到哪、为什么选它"。**主干只画一条。**
2. **填链节**：逐节填 `ID / 做什么 / 上游 / 下游 / 载体 / 单位 / 证据`。
   编号即顺序 ⇒ 填的时候天然会暴露"这里其实断了"。
3. **挂附件**：五类（R/F/I/J/K）各自声明挂在哪些链节上。
   挂的时候会暴露"这个需求/判据其实没有落点"。
4. **软件链补齐三层**（[`chain-model.md`](chain-model.md) §九）：①`## 分层` + `## 调用边`
   （谁属于谁、谁**不许**调谁）②回环 + 时序（哪几个循环并发）③链节表 `人话` 列
   （为什么存在，画到节点正面）。

**判据**：`scripts/chain.py <报告>.md` 退 0（无断链、无孤儿、无缺挂载），
且软件链**没有** ①/③ 缺失警告。

**常见坑**：
- 先挂附件再定主干 ⇒ 主干选错了，附件全要重挂。**顺序不能反。**
- 主干写成并列两条 ⇒ 那是两份报告。
- 附件只挂一个链节就交差 ⇒ 多对多才是常态（一个需求常由好几节共同保证）。
- `挂在链节` 留空 ⇒ `chain.py` 报"没人保证这个需求"——**这正是它要抓的**。
- **软件链只画执行顺序** ⇒ 只画了②时间层。读者要 ①（谁属于谁）+ ③（为什么存在），
  给一堆②就是"看不懂"——不是他看不懂，是拿画硬件的方法画了软件（§九）。
  分层/调用边/人话是必填项，不是可选项。
- `人话` 写成"做什么"的复述（"采集一帧数据"）⇒ 等于没写。人话 = "为什么存在 + 不这么做会怎样"
  （"成块搬运——边采边算会丢样"）。

## ⑤ 跑验证（**强制**）

**动作**：把工程自带的仿真 / 门禁 / DRC / 单测**全跑一遍**（先过③的对口径）。
**跑不了的要写明"跑不了 + 为什么"**（缺依赖？缺硬件？）。

**判据**：交付物里能看出"哪些结论是跑出来的，哪些是算出来的，哪些只是读出来的"。

**常见坑**：
- 拿"理论上应该"当结论。**跑不了就说跑不了**，这不丢人；假装跑过才丢人。
- 改了工程自带脚本让它通过 ⇒ 不许。要改也得单独说明。

---

## ⑥ 出两份

**动作**：HTML（给人看）+ Markdown（给 agent 读）。骨架与验收见 [`outputs.md`](outputs.md)。

**判据**：HTML 能离线打开、能看出分层与流向；MD 能独立读懂、不依赖 HTML。

**常见坑**：
- 只出一份 HTML ⇒ 下次 agent 接手要解析 HTML，贵且容易读错。**MD 是给 agent 的那份。**
- 引外链 CDN（图/字体）⇒ 离线打不开。**全部内联。**

---

## ⑦ 拷问（**固定交付项**）

**动作**：出 **5~8 个**待确认项，每项：
- 一句话说清"是什么不清楚"
- 附**你的推荐答案**（不是"你觉得呢"）
- 写清"**缺什么才能确认**"
- **能点击式问就点击式问**（有 `AskUserQuestion` 这类工具就用，一次最多 4 个，分轮）

**判据**：每个问题都能被人用一句话回答（是/不是/选哪个），**不需要先去做实验才能回答**。
需要做实验才能回答的，不是"问题"，是"任务" —— 那要写成任务。

**常见坑**：
- 问"你要不要我继续"这类空问题。
- 把"需要上板量一次"包装成"问题" ⇒ 应该写成任务 + 验收判据。
- 一次问 15 个 ⇒ 人不会答。**5~8 个，分轮。**

---

## 收工自检（四问）

1. 六条链**都在**吗？每条都有**来源列**吗？
2. 一手 vs 文档的**冲突**都登记了吗（一条都没有 = 很可能没真去核）？
3. 跑过的东西**真的跑过**吗（还是只在表里写了"应通过"）？
4. 每条"待确认"都写了"**缺什么才能确认**"吗？

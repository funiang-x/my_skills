# 链模型 —— 一条链，六类附件

> **表是分类，链是路径。** 六张表回答"有哪些"，链回答"**谁扣着谁、断在哪**"。
> 本 skill 的交付物是**一条链**：一条可走的主干，每个链节挂着它的附件。

---

## 一、结构

**一份报告里通常有两条链** —— 这是踩出来的：软硬件揉在一张图上必然糊。

| 链 | 走什么 | 粒度 | 从 → 到 |
|---|---|---|---|
| **硬件链** | **信号处理路径** | 器件 / 节点 | 输入连接器 → 端接 → 保护 → 滤波 → 放大 → 抗混叠 → **ADC 输入脚** |
| **软件链** | **软件架构** | 模块 / 函数 / 任务 | 复位 → 外设初始化 → 组合根 → 采集 → 算法 → 结果 → 界面 → 输出 |

**交界点 = 引脚**：硬件链到"信号进 ADC 脚"为止（单位一路是 mV），
软件链从"配置 ADC 寄存器"接上（单位是码值 / 结构体）。
ID 前缀各自区分（`H01…` / `S01…`），**附件可以跨链挂**（一个需求可能同时落在硬件节与软件节上）。

每条链内部：

```
        附件（挂上去的）
   R1 ──┐
   F2 ──┤
   I3 ──┼──►  H07  ──►  H08  ──►  H09  ──► ...      ← 链节顺序相扣
   J5 ──┤      ▲
   K1 ──┘      └── 上游 H06
```

**为什么这样组织**：一个工程最难回答的不是"有哪些模块"，而是
**"需求里的那个数字，顺着走，最后落在哪个器件、被哪条判据守着、坏了会怎样"**。
这条路径只能由"链节 + 挂载"表达出来。

⚠️ **不要只画一条链**。硬件链问"这个信号被谁怎么处理了"，软件链问"这段逻辑谁在什么时候跑" ——
两者的阶段、执行体、判据完全不同，合并只会互相干扰。

**软件链内部另分三层**（①结构 ②时间 ③意图）—— 这不是可选的修饰，是"软件链看不懂"的根因所在。
定义、线格式与判据见 §九。

## 二、链节（主干）

| 字段 | 必填 | 说明 |
|---|---|---|
| `ID` | ✅ | `L01`…`Lnn`，**按主干顺序编号**（编号即顺序） |
| 做什么 | ✅ | 这一跳在做什么（动词开头） |
| 人话 | 软件链 ✅ / 硬件链 ◑ | 一句大白话的"**为什么存在**"——**画到节点正面**，不是"做什么"的复述。写法与反例见 §九 |
| 上游 | ✅ | 上一节 ID；首节写 `—` |
| 下游 | ✅ | 下一节 ID；末节写 `—` |
| 载体 | ✅ | 变量名 / 寄存器 / 节点名 / 文件名。**写具体名字** |
| 单位 | ✅ | 这一节的量纲。**每节都要写**（无量的写 `—`） |
| 证据 | ✅ | 路径 + 行号 / 器件位号 + 参数 |

**主干的选法**（只选一条，不要并列）：

| 工程类型 | 主干 = | 例 |
|---|---|---|
| 信号/数据通路型 | **物理量到输出的逐跳** | 传感器 → ADC → 算法 → 屏 |
| 控制/状态机型 | **状态迁移顺序** | 上电 → 自检 → 待机 → 测量 → 上报 |
| 请求/服务型 | **一次请求的生命周期** | 入口 → 校验 → 业务 → 落库 → 响应 |

⚠️ **主干只有一条。** 有第二条主干就说明选错了 —— 应该把第二条挂成附件或另起一份报告。

## 三、附件（六类）

| 类型 | 前缀 | 回答 | 必填字段 | 挂载语义 |
|---|---|---|---|---|
| 需求 | `R` | 规格里的数字**谁保证它** | 内容 / 挂在链节 / 判据 / 证据 / 强度 | `挂在` = 哪些链节共同保证它 |
| 功能 | `F` | 功能落在哪几节 | 内容 / 落在链节 / 证据 | `落在` = 这功能体现在哪些链节 |
| 交互 | `I` | 硬件↔固件怎么对上 | 硬件实体↔固件实体 / 落在链节 / **改了要连带什么** / 证据 | `落在` = 这一节用的是哪个外设 |
| 判据 | `J` | 守着哪一节、判错什么样 | 判据 / 守在链节 / **判错症状** / 失败语义 / 证据 | `守在` = 这一节的正确性由它把守 |
| 风险 | `K` | 哪一节有隐患 | 结论 / 挂在链节 / 强度 / 依据 | `挂在` = 风险落在哪一节 |
| 冲突 | `K` | 一手 vs 文档 | 同上 + `[冲突]` 格式 | 同 `K` |

**一个链节可以挂多个附件；一个附件可以挂多个链节**（多对多）。
`chain.py` 会把"挂载数最多的链节"列出来 —— 那通常就是**整个工程最关键的几跳**。

## 四、断链判据（本模型的价值所在）

`chain.py` 自动查这 6 条，**每一条命中都是一个真发现**：

| # | 判据 | 命中意味着 |
|---|---|---|
| 1 | 主干从首节出发**走不到末节** | 链断了 —— 中间有节没接上 |
| 2 | 某节既无上游也无下游，且不是首/末节 | 孤儿链节 —— 画上去但没接进主干 |
| 3 | 上游/下游**互指不一致**（A 说下游是 B，B 说上游不是 A） | 链写错了，会导致"走链"走错 |
| 4 | 某条 `R` **没有挂到任何链节** | **没人保证这个需求** —— 最严重的一类 |
| 5 | 某条 `J` 没有挂在任何链节 | 判据悬空：不知道它守什么 |
| 6 | 某条 `K` 没有挂在任何链节 | 风险没定位：不知道改哪里 |

**第 4 条最值钱**：需求表里每条都"写了判据、写了实体"，但走链才发现
**它压根没落在主干上** —— 那就等于没人做。

## 五、Markdown 线格式（`scaffold.py` 生成、`chain.py` / `check_report.py` 解析）

````markdown
## 链节（主干）

| ID | 做什么 | 人话 | 上游 | 下游 | 载体 | 单位 | 阶段 | 执行体 | 证据 |
|---|---|---|---|---|---|---|---|---|---|
| L01 | 信号源 → 连接器 | 把源头的信号引进来 | — | L02 | `J1.1` | V_emf (mV) | 模拟段 | Analog | AFE 页 |
| L02 | 50Ω 端接 | 不配就反射，幅值全错 | L01 | L03 | `$3N702` | mV ×0.5 | 模拟段 | Analog | AFE 页 |

## 回环

| 从 | 到 | 为什么 |
|---|---|---|
| L23 | L16 | 切页 → 通知 engine 立刻重测 |

## 附件

### 需求（R）

| ID | 内容 | 挂在链节 | 判据 | 证据 | 强度 |
|---|---|---|---|---|---|
| R1 | u_a Upp 100~250mV | L02,L07,L10 | ±5mV | `...` | 已核 |

### 功能（F）

| ID | 内容 | 落在链节 | 证据 |
|---|---|---|---|
| F1 | 测量编排 | L13,L14,L15 | `...` |

### 交互（I）

| ID | 硬件实体 | 固件实体 | 落在链节 | 改了要连带什么 | 证据 |
|---|---|---|---|---|---|
| I1 | `TIM8` | `BOARD_TIM8_ARR` | L13 | 改 fs ⇒ 标定表全废 | `...` |

### 判据（J）

| ID | 判据 | 守在链节 | 判错症状 | 失败语义 | 证据 |
|---|---|---|---|---|---|
| J1 | buf 不落在 CCM | L14 | 采集恒 0 不报错 | 拒绝启动 | `...` |

### 风险（K）

| ID | 结论 | 挂在链节 | 强度 | 依据 |
|---|---|---|---|---|
| K1 | 相位折回 | L20 | 已核 | `...` |
````

**解析规则**（`chain.py` 实现）：
- 表归属到最近的 `### xxx（前缀）` 标题；标题里的括号内单字母即附件前缀。
- 链节表 = `## 链节（主干）` 下的第一张表；`阶段` / `执行体` / `人话` **可缺省**
  （缺阶段不分带、缺执行体不着色、缺人话节点正面退回「做什么」——**软件链缺人话会被告警**，见 §九）。
- `挂在链节` / `落在链节` / `守在链节` 列里是**逗号分隔的链节 ID 列表**。
- 表格里的反引号会被剥掉（`L02` 与 `` `L02` `` 等价）。

## 六、渲染规则（`render.py`）—— **按逻辑排，不按顺序排**

⚠️ **一条直线排到底，会把「阶段 / 并发 / 回环」这三件事全压平** —— 而它们恰好是链的价值所在。
所以渲染按下面的规则（不是"从左到右走一遍"）：

| 规则 | 怎么落地 |
|---|---|
| **阶段 = 横带** | 按 `阶段` 字段分组，**自上而下**堆叠；每带一个圆角底 + 带名 + `stage N` |
| **带内折行** | 带内节点**左→右**排，每行最多 `COLS`(=4) 个，超出换行 |
| **主干连线** | 按 **ID 顺序**（不是坐标顺序）连：同一行向右画直箭头；折行/跨带画肘形（下→横→下） |
| **执行体 = 颜色** | 节点左侧色条 + 描边按 `执行体` 取色 ⇒ **并发一眼看出**（Analog / Init / ISR / Engine / Ui / Driver） |
| **人话 = 正面** | 节点正面第一行画 `人话`（③意图层），没有才退回「做什么」；点开面板的黄框是同一来源（旧报告写在讲解表「人话」角度的也兼容） |
| **回环单列** | 画在所属链的**下方**，红色虚线弧 + 一句"为什么"；**不混进主干** |
| **软件结构页签** | 有 `## 分层` 就多一个「软件结构」页签（①结构层）：层 = 横带（层名 + 职责 + ✗不许做什么 + 该层链节）；`## 调用边` 画成层间箭头（`从`/`到` 填**层名**），跨层调用 = 橙色虚线（全工程只应有一处） |
| **附件不画线** | 只在节点右下角画小圆点；要看关系就点节点（面板列详情）或点下方附件标签（高亮节点） |
| **一条链一张图** | 多条链用**页签**切换，不上下堆叠 |
| **留白** | 阶段带之间留 `BAND_GAP`，带内留 `PAD`，节点不贴边 |

**交互**（单文件 HTML，无外链）：
- **默认一条附件线都不画。** 几十条汇聚线画出来没人看得懂（实测：89 条线 = 一团乱麻）。
  附件改成：① 节点右下角一个小圆点；② 点节点 → 右侧面板列出它的全部附件；
  ③ 下方附件面板里点某个 `R1/F3/J9` → **高亮它挂的节点**（加粗描边 + 其余淡出），**不画线**。
- 点**链节** ⇒ 右栏按这个顺序显示：**人话（大字）** → 上一节 / 下一节（**可点跳转**，带名字）
  → 载体 / 单位 / 证据 → 其余讲解角度 → 挂在它上面的附件。
  ⚠️ **不要把整条上下游路径列成一串 ID**（`H03 → H04 → … → H17`）—— 那是噪音；
  只给**紧邻一节**，且要带名字、可点。
  ⚠️ **人话必须在最上面**。技术元信息（载体/单位/证据）往下放。
- `chain.py --html` 出图后会**自动用 `node --check` 验一次内嵌 JS 的语法**（有 node 就验）。
  **JS 语法错会让交互静默失效**（页面照常显示、点谁都没反应），而 HTML"看着是对的"——
  肉眼查不出来，必须机器验。
- **一条链一个页签**（硬件链 / 软件链），不是上下堆叠 —— 一次只看一条。
- 顶部图例列出所有出现过的**执行体**及其颜色。

## 七、讲解（`## 讲解` 段）—— **只列"有什么"不算交付**

链节表只写得下"**是什么**"。一个链节真正的信息量在另外几个角度上：

| 角度 | 回答 | 不写会怎样 |
|---|---|---|
| **是什么** | 职责一句话 | — |
| **为什么** | 设计意图；**不这么做会怎样** | 读者只知道有这个东西，不知道为什么要有 |
| **怎么做** | 实现细节 + 参数 | 换个人没法改 |
| **关键数字** | 值 + **推导** + 单位 | 数字变成"祖传常数" |
| **边界** | 什么条件下成立 / 依赖哪些假设 | 条件一变就静默出错 |
| **失效** | 错了会看到什么现象 | 现场排障只能猜 |

**角度是自由的** —— 想加"成本角度""时序角度""热角度"就往表里加一行。
`chain.py` 只认列名 `角度` / `内容`，不认具体是哪些角度。

线格式：

````markdown
## 讲解

### H13 · 同相放大

| 角度 | 内容 |
|---|---|
| 是什么 | `U1B` 把信号放大 7.9748 倍，参考点是 VBIAS 而不是地 |
| 为什么 | 前面两级各损失一半，要补回净增益 2；R7 接 VBIAS 是为了让输出直流自动落在 ADC 半量程 |
| 怎么做 | `R6 24.9k` 输出→反相端，`R7 3.57k` 反相端→VBIAS；增益 = 1 + R6/R7 |
| 关键数字 | ×7.9748；闭环带宽 = GBW/gain = 1.254 MHz |
| 边界 | 绝对阻值由 H2 改图改过（比值不变），目的是降 R7 热噪声 |
| 失效 | R7 接地 ⇒ 直流增益也 ×7.97 ⇒ 输出 13.16V 贴轨 |
````

**判据**（`check_report.py` 自动查）：
- 一个链节都没写讲解 ⇒ **失败**（那只是清单，不是分析）
- >30% 的链节没写 ⇒ 警告
- 某个链节只有 1 个角度 ⇒ 警告（一个角度等于没说）

渲染：图上的节点点开就是这张表；另有**"逐节讲解"页签**把全部链节的讲解平铺出来，便于通读。

## 八、时序（`## 时序` 段）—— **软件链看不懂，多半是缺了这张表**

一条**线性**的软件链会把「两个循环在并发」压成「顺序走一遍」——
这是"软件链看不懂"最常见的原因。补两样东西：

1. **循环回边**（写进 `## 回环`）：`S15 → S06`（Engine 循环）、`S19 → S16`（Ui 循环）。
   有了这两条，读者才知道 S06–S15 与 S16–S19 是**两个各转各的圈**，不是一条流程。
2. **运行时序**（本节）：谁在什么时候跑、跑多久、谁等谁。

线格式：

````markdown
## 时序

| 车道 | 周期 (ms) | 起点 (ms) | 段 | 时长 (ms) | 说明 |
|---|---|---|---|---|---|
| Engine | 500 | 0 | 等通知 | 485 | 睡满一拍；被 UI 叫醒则立即返回 |
| Engine | 500 | 485 | 采样窗 | 2.05 | 抢闸 → 采 → 放闸 |
| Engine | 500 | 487.05 | DSP 链 | 13 | FFT + 找峰 + 标定 + 四口径 |
| Engine 工作段 | 15.15 | 0 | 采样窗 | 2.05 | ↑ 同一段放大看 |
| ISR | 500 | 487 | 搬满一帧 | 0.02 | 采样窗结束时触发一次 |
| Ui | 10 | 0 | 取快照 + 重建 | 1 | 每 10ms 一次 |
````

**渲染规则**（`render.py`）：
- **每条车道按自己的周期归一化** —— 横轴是"一个周期的百分比"，**不是同一条时间轴**
  （Engine 一圈 500ms、Ui 一圈 10ms，混在一起画必然误导）。
- `起点` 缺省时按"段时长累加"排；给了数就按它定位（用于把 ISR 钉在采样窗末端）。
- 车道名可以带后缀（`Engine 工作段`）—— 配色按**前缀匹配**，复用 `Engine` 的色。
- ⚠️ **必须有一条"放大"车道**：500ms 尺度下"采样窗 2.05ms"只有 3.8px，等于没画。
  做法就是再给一组同样段、但 `周期` 填工作段总长的行。

## 九、软件链的三层（①结构 · ②时间 · ③意图）—— 只画一层 = 拿画硬件的方法画软件

**硬件链天然是一条线**：信号在空间里顺序流过器件，"归谁管（哪级电路）""什么时候（顺序即时间）"
"为什么存在（每级的目的）"都**附着在同一条路径上**，一张图就够。
**软件不是。** 软件的静态结构、运行时间、设计意图是**三件不同的事**——把它们压成一条
"复位→初始化→采集→算法→界面"的线，就只剩下 ②时间层。读者要的是 ① + ③，你给了一堆 ②，
他的感受就是"看不懂"；不是他看不懂，是**拿画硬件的方法画了软件，再用他没见过的词去解释**。

| 层 | 问什么 | 数据在哪 | 画在哪 |
|---|---|---|---|
| **① 结构层** | **归谁管**：谁调用谁、谁**不许**调谁（Task / Operation / Device） | `## 分层` + `## 调用边`（线格式见下） | 「软件结构」页签 |
| **② 时间层** | **什么时候跑**：哪几个循环并发、谁等谁 | `阶段`/`执行体` 列 + `## 回环` + `## 时序`（§八） | 主图（阶段带 + 执行体着色）+「运行时序」页签 |
| **③ 意图层** | **为什么存在**：为什么要锁屏幕 / 为什么要减平均 / 为什么要等 130ms | 链节表 `人话` 列 | **节点正面**（不是点开才看到）+ 面板黄框 |

**三条缺一 = 只交付了②。** `chain.py` 对软件链查三层覆盖：缺①（分层 / 调用边）、缺③（人话）
给**警告**——软件链里它们是必填项，不是可选项（纯硬件报告不受影响）。

### 线格式

````markdown
## 分层（软件链 ① 结构层）

> `节点` 列填本链链节 ID（逗号分隔）；`不许做什么` 与"谁调谁"同等重要——那才是设计意图。

| 层 | 归属（职责） | 不许做什么 | 节点 |
|---|---|---|---|

## 调用边（软件链 ① 结构层）

> `从`/`到` 填**层名**（渲染成层间箭头）。跨层调用全工程只应有一处；写出第二处 = 分层漏了。

| 从 | 到 | 为什么允许 |
|---|---|---|
| 应用 | 驱动 | 经 bsp_* API；参数注入，不读硬件头 |
````

**人话的写法**（③）：一句"为什么存在 + 不这么做会怎样"的大白话，**不是"做什么"的复述**：

| ❌ 复述（等于没写） | ✅ 人话 |
|---|---|
| 采集一帧数据 | 成块搬运——边采边算会丢样 |
| 等待 130ms | 等传感器首次稳定，否则首帧偏差直接进结果 |
| 减去平均值 | 去掉直流漂移，否则增益误差全进读数 |

**人话不是类比。** 要去掉的是术语与缩写，不是严谨性：
"锁屏幕，免得电钻吵"（✗ 比喻，读者还要反推你防的是什么）→
"采样窗前取得 LCD 总线闸，隔离写屏干扰"（✓ 直述动作与意图）。
判据：同行读完不需要追问"这个比喻指什么"，就知道这一节防的是什么失效。

节点正面只放得下一行：先给意图；"做什么"退到点开后的面板标题。
**单一真相源**：`人话` 写在**链节表的人话列**（节点正面与面板都从它来）；
讲解表里的「为什么」是它的展开版，不要再写一个「人话」角度
（旧报告写了也兼容：面板优先读链节表列，没有才退回讲解表）。

**裸机单循环怎么办**：也至少写一层（层名可就叫 `全部`），并在「不许做什么」里写清
"为什么不需要更多层"——没有分层不是"没有结构"，是"没分析"。

# swhw-chain —— 软硬件逻辑链分析（硬件链 + 软件链）

## 它解决什么问题

一个软硬一体的工程，最难回答的从来不是"有哪些模块"，而是：

> **需求里的那个数字，顺着走，最后落在哪个器件、被哪条判据守着、坏了会怎样？**

分类（"有哪些需求/功能/器件"）回答不了这个问题 —— **只有链能**。
所以本 skill 的交付物是**一条链**，不是六张并排的表。

## 链长什么样

**一份报告里通常有两条链，各画各的** —— 揉在一张图上必然糊：

| 链 | 走什么 | 粒度 | 例（从 → 到） |
|---|---|---|---|
| **硬件链** | **信号处理路径** | 器件 / 节点 | `J1`(SMA) → 端接 → 保护 → 滤波 → 放大 → 抗混叠 → **ADC 引脚** |
| **软件链** | **软件架构** | 模块 / 函数 / 任务 | 复位 → 外设初始化 → 组合根 → 采集 → 算法 → 结果 → 界面 → 屏 |

两条链在**引脚**处交界（硬件链到 ADC 输入脚为止，软件链从寄存器配置接上）。
ID 前缀各自区分（`H01…` / `S01…`），附件按 ID 挂到对应链上（可跨链）。

**软件链内部再分三层看**：①结构（归谁管：分层 + 调用边）②时间（什么时候跑：回环 + 时序）
③意图（为什么存在：人话上节点正面）。只画② = 拿画硬件的方法画软件 —— 这是"软件链看不懂"的根因，
见 [`references/chain-model.md`](references/chain-model.md) §九。

每条链内部：

```
   R1 ──┐
   F2 ──┤
   I3 ──┼──► H07 ──► H08 ──► H09 ──► ...     ← 链节顺序相扣
   J5 ──┤      ▲
   K1 ──┘      └── 上游 H06
```

- **链节按顺序编号**（`H01`…/`S01`…），每节写清 `上游 / 下游 / 载体 / 单位 / 阶段 / 执行体 / 证据`。
- **五类附件**（R/F/I/J/K）各自声明**挂在哪些链节**上（多对多）。
- **挂载最多的那几节 = 最关键的几跳**（`chain.py` 会列出来）。

完整定义（字段、挂载语义、线格式、渲染规则）见 [`references/chain-model.md`](references/chain-model.md)。
五类附件各自的填写要求与反例见 [`references/six-chains.md`](references/six-chains.md)。

## 断链检查（本 skill 最值钱的部分）

`chain.py` 自动查 6 条，**每一条命中都是一个真发现**：

| # | 命中意味着 |
|---|---|
| 1 | 从首节走不到末节 ⇒ 链断了 |
| 2 | 某节既无上游也无下游且不是首/末节 ⇒ 孤儿链节 |
| 3 | 上游/下游互指不一致 ⇒ 链写错了 |
| 4 | **某条需求没挂到任何链节 ⇒ 没人保证它**（最严重） |
| 5 | 某条判据没挂在任何链节 ⇒ 判据悬空，不知道它守什么 |
| 6 | 某条风险没挂在任何链节 ⇒ 风险没定位，不知道改哪里 |

> 第 4 条最值钱：需求表里"写了判据、写了实体"看着很完整，**走链才发现它压根没落在主干上** ——
> 那等于没人做。
>
> 另查**软件链三层覆盖**（警告级）：软件链缺 `## 分层` / `## 调用边`（①结构）、多数链节没有
> `人话`（③意图）—— 只画了②时间层 = 拿画硬件的方法画软件。

## 铁律（六条，破了就等于没做）

1. **一手为准。** 只把源码 / 网表 / `.ioc` / 生成物当证据；文档（`docs/`、`*.md`）**只用于交叉核对**，
   冲突时以一手为准，并把冲突**登记**进附件 `K`（格式见 `references/evidence-rules.md`）。
   > 实战：某工程四处文档写「FSMC DS=85」，`.ioc` 与生成码是 `DS=12` —— 那个"85"**从未落地**。

2. **先对口径，再信数字。** 跑工程自带的仿真/门禁之前，先确认"仿真的口径与实现是不是同一个"。
   > 实战：仿真建相位表用了 `np.unwrap`，固件存 `atan2` 主值 ⇒ 仿真把一个 180° 的缺陷藏了，长期绿灯。
   > **仿真绿 ≠ 电路对。**

3. **每个数字都要有来源。** 链节与附件的「证据」列必须能落到"哪个文件的哪一段 / 哪个器件"。

4. **待确认必须闭环。** 每条待确认都要写清 **缺什么才能确认**（量一次？问人？换料？）。

5. **软件链必须画全三层（①结构 ②时间 ③意图）。** 只画"什么时候跑" = **拿画硬件信号路径的方法画软件**
   —— 硬件链三件事附着在同一条信号路径上，软件的三件事是三张不同的图，压成一条线就只剩②；
   而读者要的恰恰是 ①（谁属于谁、谁**不许**调谁）和 ③（为什么存在）。必做三件：
   **① `## 分层` + `## 调用边`**（出「软件结构」页签）
   + **② 补循环回边**（`S15→S06` / `S19→S16`）**+ 配运行时序**（各执行体按自己周期归一化）
   + **③ 人话上节点正面**（链节表 `人话` 列：为什么要锁屏幕 / 为什么要减平均 / 为什么要等 130ms
   —— 不是"做什么"的复述）。见 [`references/chain-model.md`](references/chain-model.md) §八 §九；
   缺①③ `chain.py` 会警告。

6. **只列"有什么"不算交付。** 每个链节必须**从多个角度讲清楚**：
   `是什么 / 为什么 / 怎么做 / 关键数字 / 边界 / 失效`（角度自由，可增删）。
   链节表写得下"是什么"，写不下"**为什么**"和"**错了会怎样**" —— 而那两条才是读者真正要的。
   **一个链节都没写讲解 = 交付失败**（`check_report.py` 会拦）。
   见 [`references/chain-model.md`](references/chain-model.md) §七。

## 工作流（九步，顺序固定）

| 步 | 做什么 | 工具 |
|---|---|---|
| ① 划范围 | 哪几个目录、哪几页原理图；排除 build / vendor / 第三方 | [`scripts/inventory.py`](scripts/inventory.py) |
| ② 取一手 | 读源码全文（**不读 docs**）+ 取网表（**带元件值**） | [`scripts/relations.py`](scripts/relations.py) · [`scripts/netlist.py`](scripts/netlist.py) |
| ③ 对口径 | 工程自带仿真/门禁的口径 vs 实现口径 | 人工 + 工程自带脚本 |
| ④ 搭链 | 生成骨架 → **先定主干**（哪条通路）→ 填链节（含 `人话` 列）→ 挂附件 → **软件链补齐三层**（①`## 分层`+`## 调用边`） | [`scripts/scaffold.py`](scripts/scaffold.py) |
| ⑤ 跑验证 | **强制**：能跑的仿真/门禁/DRC 都跑；跑不了写明"跑不了 + 为什么" | 工程自带 |
| ⑥ 出两份 | HTML 由 `chain.py --html` **从 MD 生成**（多链页签 + 阶段横带 + 折行 + 执行体着色 + 回环区 + **逐节讲解页签**），MD 给 agent 读 | 见 [`references/outputs.md`](references/outputs.md) · [`scripts/render.py`](scripts/render.py) |
| ⑦ 写讲解 | **逐节从多个角度讲清楚**（人话 / 是什么 / 为什么 / 怎么做 / 关键数字 / 边界 / 失效）—— 角度自由，`chain.py` 只认列名 | 见 [`references/chain-model.md`](references/chain-model.md) §七 |
| ⑧ 画时序 | **软件链必须配一张运行时序**（各执行体按自己周期归一化）—— 线性链会把"并发循环"压成"顺序走一遍" | 见 [`references/chain-model.md`](references/chain-model.md) §八 |
| ⑨ 查 + 拷问 | `chain.py` 查断链 → 出 5~8 个待确认项，每项附推荐答案 | [`scripts/chain.py`](scripts/chain.py) |

详细步骤与常见坑见 [`references/workflow.md`](references/workflow.md)。

## 用法

```bash
SK=~/.ai-skills/swhw-chain/scripts

# ① 划范围
python "$SK/inventory.py" <工程根> --out <产物目录>/_work/scope.md

# ② 一手取证
python "$SK/relations.py" <工程根>/src --md <产物目录>/_work/relations.md
python "$SK/netlist.py" --project <EDA 工程名> --out <产物目录>/_work/netlist.md
#   （连接器不在线时走降级：--from-json <之前存的 raw 目录>）

# ④ 搭链（然后先定主干，再填链节与附件）
python "$SK/scaffold.py" --topic <主题> --out <工程根>/docs/chain

# ⑦ 查链：断链 / 孤儿 / 缺挂载 + 热点 + 走链
python "$SK/chain.py" <工程根>/docs/chain/<主题>-<日期>.md
python "$SK/chain.py" <工程根>/docs/chain/<主题>-<日期>.md --walk L07

# 出图：**从 MD 生成 HTML**（不要手写 HTML —— 手写必然与 MD 漂移）
python "$SK/chain.py" <工程根>/docs/chain/<主题>-<日期>.md \
       --html <工程根>/docs/chain/<主题>-<日期>.html

# 自检（链完整性 + 冲突登记 + 验证记录 + 拷问清单 + 引用路径）
python "$SK/check_report.py" <工程根>/docs/chain/<主题>-<日期>.md --root <工程根>
```

**出图的要点**（`references/chain-model.md` §六）：阶段按 `阶段` 字段分横带**自上而下**堆叠，
带内左→右折行；节点按 `执行体` 上色（并发一眼看出）；回环画在下方；
**`人话` 直接画在节点正面**（不藏进点开的表）；附件**不画线**（节点右下角小圆点 +
点节点看详情、点附件标签高亮节点）；软件链另有「**软件结构**」页签（`## 分层` 横带 +
`## 调用边` 层间箭头，`从`/`到` 填层名）与「**运行时序**」页签（各执行体按自己周期归一化）。
⚠️ **不要把主干排成一条从左到右的长线** —— 那会把阶段、并发、回环三件事全压平，
而它们恰好是链的价值所在。

**产物落点**：默认 `<工程根>/docs/chain/<主题>-YYYYMMDD.{html,md}`。
⚠️ 工程自己的 `AGENTS.md` / `docs/INDEX.md` 若另有编号约定，**以工程为准**（`ROUTE.md` §2 通用规则 1）。

## 边界（别越界）

- **不改工程。** 只读 + 只写产物目录；改代码/改图是别的 skill 的事。
- **不烧录、不下单、不改 `.ioc` 的引脚/时钟。**
- **主干只画一条。** 想画第二条 ⇒ 说明主干选错了，回去重选（或另起一份报告）。
- **仿真跑不出结论就写"跑不出"**，不许拿"理论上应该"当结论。
- **硬件侧"要实物才能确认"的不要伪装成结论** —— 触摸映射、真实吞吐、实际料号，一律进拷问清单。
